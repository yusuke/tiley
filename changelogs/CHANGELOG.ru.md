# Журнал изменений

## [Unreleased]

### Исправлено

- При редактировании пресета раскладки, в котором уже были слоты с назначенными приложениями, номер внутри перетаскиваемого прямоугольника (и его цвет) был на единицу больше нужного: назначенные слоты учитывались, хотя показывают значок вместо номера. Предпросмотр при перетаскивании и наведении теперь использует ту же нумерацию, что и подтверждённые прямоугольники.
- При каждом переключении фокуса или окна в любом приложении Tiley выполнял полный опрос Accessibility по всем открытым окнам (плюс запрос списка окон у WindowServer) — даже если функция группировки окон вообще не использовалась. Обновление бейджей теперь завершается сразу, если нет ни связанных групп, ни ожидающих кандидатов в группы, а события смены фокуса объединяются, так что одно переключение окна (порождающее сразу два уведомления Accessibility — о смене фокусного и главного окна) вызывает не более одного обновления вместо двух. Это устраняет постоянную фоновую нагрузку на CPU/IPC при обычном переключении приложений.
- Оверлей Tiley при каждом проходе рендеринга SwiftUI заново считывал с диска метаданные обоев и конфигурацию Dock: plist хранилища обоев повторно разбирался до четырёх раз за проход (а файл обоев заново открывался для чтения размеров в пикселях), а при видимом крае Dock каждый раз заново загружались plist Dock и иконки всех его приложений — синхронный дисковый ввод-вывод в главном потоке с частотой движения мыши. Теперь сведения об отображении обоев кэшируются для каждого экрана и сбрасываются при смене обоев или конфигурации экранов, а содержимое Dock читается один раз при каждом открытии окна.
- Перетаскивание выделения по сетке перестраивало оверлей предпросмотра экрана при каждом событии мыши: каждое движение заново создавало всю hosting view SwiftUI оверлея, даже если подсвеченные ячейки не менялись. Теперь предпросмотр обновляется только тогда, когда выделение действительно переходит в другую ячейку, а оверлей повторно использует одну hosting view вместо её пересоздания — пик нагрузки на CPU при перетаскивании устранён (то же повторное использование применяется к предпросмотрам наведения на пресеты, изменения размера и сетки настроек).
- Перемещение или изменение размера связанной группы окон опрашивалось на частоте 120 Гц синхронными вызовами Accessibility, при изменении размера выполнялось до трёх циклов проверки и коррекции на каждое ведомое окно за тик, а поиск окон выполнялся линейным сканированием сотни раз в секунду. Теперь опрос работает на 60 Гц с одной проверкой за тик (итоговые позиции по-прежнему фиксирует коррекция при отпускании), поиск окон идёт через индекс O(1), а ведомым приложениям на время перетаскивания задаётся короткий тайм-аут обмена сообщениями Accessibility, так что одно занятое приложение больше не может застопорить Tiley посреди перетаскивания.
- При наличии связанных групп или бейджей группировки групповые операции перечитывали позиции окон гораздо чаще, чем нужно: создание, роспуск или перепроверка группы сканировали позицию каждого открытого окна синхронными чтениями Accessibility по несколько раз за событие (один клик по спаренному окну мог вызвать от шести до восьми полных сканирований), а обновления бейджей сканировали все окна при каждой смене фокуса. Теперь все эти пути читают только действительно задействованные окна (участников группы и кандидатов на бейджи), поэтому объём обмена с Accessibility на событие больше не растёт с общим числом открытых окон.
- Применение раскладки больше не блокирует приложение. Последовательность перемещения окон (которая намеренно выжидает между шагами Accessibility, чтобы пересилить приложения, откатывающие позицию) выполнялась последовательно в главном потоке — пресет из четырёх окон блокировал Tiley на 200 мс и более, плюс около 100 мс на приложение для последовательности поднятия окон. Теперь перемещения выполняются в фоновых потоках, независимые окна двигаются параллельно, ожидания при поднятии не блокируют главный поток, а быстрые повторные применения ставятся в очередь с сохранением порядка. Тайминги шагов Accessibility для каждого окна не изменились.
- Запрос окно→Space выполнял по одному обращению к WindowServer на окно при каждом обновлении списка окон (то есть после каждого переключения приложений). Теперь привязки к Space кэшируются на короткое время (не более пяти секунд, кэш сбрасывается при смене Space), а монитор групп, разнесённых по Spaces — намеренно обходящий кэш — проверяет раз в две секунды вместо каждой секунды.
- Строки бокового меню заново определяли партнёров по групповым связям линейным сканированием и запросами bundle-идентификатора для каждой строки при каждом проходе рендеринга, а из-за дефекта кэша запрос имени приложения для поля поиска у большинства приложений каждый раз заново читал Info.plist с диска (отрицательный результат никогда не сохранялся). Теперь определение партнёров сразу завершается для окон без связей и использует индексированные запросы, а оба кэша имён сохраняют и отрицательные результаты.
- Первое нажатие клавиши переключения окон после открытия оверлея и определение целевого окна на некоторых путях по-прежнему выполняли полный синхронный перебор Accessibility всех открытых окон в главном потоке — задержка свыше 100 мс при большом числе окон. Теперь оба пути повторно используют список, уже выровненный по актуальному порядку окон на момент открытия, и прибегают к синхронному захвату только когда списка нет вовсе (первый запуск); авторитетное фоновое обновление сверяет данные мгновением позже.
- В конфигурациях с несколькими дисплеями каждый экран без значка состояния в строке меню заново сэмплировал свои обои при каждом проходе рендеринга, чтобы выбрать цвет текста миниатюрной строки меню — с растеризацией изображения и построением гистограммы примерно по 50 000 пикселей за проход. Теперь выбранный цвет кэшируется для каждого экрана и пересчитывается только при смене обоев или конфигурации экранов.
- При зарегистрированных спутниковых связях каждое событие перемещения или изменения размера любого окна выполняло запрос к Launch Services по одному разу на каждый зарегистрированный бандл приложения ещё до проверки, относится ли перемещённое окно к какой-либо паре — многократно в секунду во время любого перетаскивания окна. Теперь проверка релевантности выполняется первой с помощью дешёвых сравнений идентификаторов, а запрос бандла происходит только для событий, действительно затрагивающих связанную пару.
- Кнопки с выпадающими меню на панели действий (перемещение на дисплей / изменение размера) принудительно выполняли полную перерисовку AppKit при каждом проходе обновления SwiftUI — с частотой наведения или нажатий клавиш — и каждая перерисовка заново тонировала их изображения SF Symbol, копируя и перерисовывая битмапы. Теперь кнопки перерисовываются только при изменении входных данных, которые отрисовка действительно использует, а тонированные изображения символов кэшируются по символу, размеру, оттенку и оформлению (при смене темы цвета по-прежнему рендерятся заново).
- Панели бейджей группировки полностью перерисовывались при каждом обновлении бейджей — каждое обновление заново строило дерево представлений SwiftUI каждого бейджа и заново задавало положение его панели, даже если ничего не изменилось. Теперь бейджи сравниваются со своим предыдущим состоянием и пропускают перерисовку, когда позиция, состояние и флаги наведения не изменились.
- Массовые действия с окнами (перемещение всех окон приложения или целого экрана на другой дисплей, закрытие нескольких окон, скрытие приложений) планировали по одному полному обновлению списка окон на каждое затронутое окно. Теперь они объединяются в одно отложенное обновление, поэтому стоимость захвата после действия остаётся постоянной независимо от числа затронутых окон.
- Каждый запуск из папки «Программы» синхронно запускал `hdiutil info` (что может занимать сотни миллисекунд) в главном потоке, чтобы проверить, не смонтирован ли ещё образ диска Tiley — а при обнаружении выполнял второй `hdiutil` лишь для разрешения пути, который первый запрос уже вернул. Теперь обнаружение выполняется в фоне и возвращается в главный поток только при реальном обнаружении смонтированного образа; избыточный второй запрос устранён, а очистка (извлечение/корзина) после перезапуска тоже больше не блокирует старт.
- Окно настроек заново разрешало идентификационные отпечатки подключённых дисплеев и перестраивало набор пресетов по умолчанию при каждом проходе рендеринга — на каждом тике при перетаскивании ползунков сетки. Теперь оба результата мемоизированы и пересчитываются только при реальном изменении конфигурации экранов или размера сетки.
- Редактирование пресета (переименование, назначение приложений, правка прямоугольников) снимало и заново регистрировало все глобальные горячие клавиши пресетов при каждом изменении, как и изменение порядка. Теперь перерегистрация происходит только когда правка действительно затрагивает горячие клавиши пресета; изменение порядка и создание новых пресетов полностью её пропускают.
- При включённом отладочном журнале каждая строка открывала, дописывала и закрывала файл журнала — делая высокочастотные пути ограниченными вводом-выводом именно во время их измерения. Дескриптор файла теперь открывается один раз и переиспользуется.
- Кнопка изменения размера в боковой панели при каждом проходе отрисовки SwiftUI (при каждом наведении, нажатии клавиши или наведении на пресет, по разу на каждый дисплей) читала положение окна синхронным вызовом Accessibility к целевому приложению и каждый раз запрашивала его значок. Занятое целевое приложение могло подтормаживать оверлей на каждом проходе. Теперь положение окна читается один раз при фактическом открытии меню изменения размера, значок берётся из кэша окон, а список пресетов размера, помещающихся на экран, кэшируется по размеру экрана.
- При каждом начале перетаскивания по сетке (и каждый раз, когда указатель покидал сетку и возвращался) полноэкранное окно предпросмотра раскладки уничтожалось и создавалось заново (новый NSWindow с hosting view и буфером размером с экран); кроме того, при перетаскивании за пределами сетки каждое событие мыши перезаписывало состояние выбранного пресета, заставляя оверлей на всех дисплеях перерисовываться с частотой событий мыши. Теперь окно предпросмотра сохраняется, пока открыт интерфейс Tiley, и освобождается только при закрытии оверлея или изменении конфигурации экранов; перетаскивание за пределами сетки сообщает о переходе один раз, а записи выбора пресета без изменений пропускаются.
- Слой модели запрашивал значки приложений и идентификаторы бандлов через Launch Services при каждом проходе отрисовки SwiftUI и при каждой смене ячейки сетки (предпросмотр окон мини-рабочего стола, живой предпросмотр раскладки и наведение на пресет, которое дважды перебирало все открытые окна), и поскольку каждый запрос возвращал новый объект значка, представления предпросмотра никогда не распознавались как неизменённые. Теперь эти запросы идут через кэш по процессам (сбрасываемый при завершении процесса), так что одинаковые входные данные дают одинаковые значения и представления пропускают перерисовку; окно предпросмотра также больше не запрашивает вывод на передний план при каждой смене ячейки.
- Tiley отслеживает перемещение и изменение размера всех окон, чтобы предлагать значки «создать группу», и при каждом таком событии считывал положение и размер окна из приложения двумя синхронными вызовами Accessibility — а затем отбрасывал результат. Поэтому перетаскивание любого окна в любом приложении стоило два обращения к перетаскиваемому приложению на каждое событие. Это чтение убрано; уведомления о смене окна с фокусом и главного окна (оба срабатывают при одном клике) теперь запускают связку поднятия один раз вместо двух, а уведомления уровня приложения регистрируются один раз на приложение, а не на каждое окно.
- При каждом переключении приложений (Cmd-Tab или клик в другое приложение) выполнялся запрос списка окон к WindowServer и полная пересортировка кэшированного списка окон Tiley, результат которой никогда не отображался (оверлей заново выравнивает кэш в момент открытия), а через 200 мс отправлялся синхронный запрос Accessibility к только что активированному приложению, даже если групп окон не было вовсе, — так что зависшее приложение могло остановить Tiley на шесть секунд стандартного тайм-аута. Лишнее выравнивание убрано, проверка групп теперь выполняется до любого вызова Accessibility, флаг разрешения Accessibility записывается только при реальном изменении, а Tiley задаёт для всего процесса тайм-аут Accessibility в одну секунду, чтобы зависшее приложение больше не могло блокировать его на секунды.
- При отпускании окна после перемещения или изменения размера — в любом приложении — Tiley считывал положение и размер всех открытых окон синхронными вызовами Accessibility (по два на окно, в главном потоке), чтобы проверить, не соприкоснулось ли перемещённое окно с другим. При 30–40 окнах это давало 60–80 обращений за одно перетаскивание, а тот же проход мог выполняться дважды за жест. Теперь проверка читает только перемещённые окна и те окна на экране, чьи текущие границы находятся рядом с ними (отобранные одним запросом списка окон), а таймер стабилизации перезапускается вместо пересоздания при каждом событии перемещения.
- После применения раскладки окна, только что расставленные Tiley, иногда обрабатывались так, будто пользователь перетащил их вручную: запоздалые уведомления Accessibility о перемещении от приложений приходили уже после того, как подавление собственных перемещений Tiley заканчивалось, из-за чего запускалась проверка соседства для ручных перемещений по всем окнам на экране и появлялись значки «создать группу» между расставленным окном и не связанным с ним окном позади, край которого случайно совпадал, — так на только что сгруппированной грани мог появиться лишний значок связи. Теперь Tiley запоминает положение расставленных им окон, чтобы такие запоздалые уведомления распознавались как эхо его собственных перемещений.
- Несколько небольших операций за проход отрисовки окна оверлея повторялись при каждом наведении, нажатии клавиши или перетаскивании, по разу на каждый дисплей: имя каждого экрана заново запрашивалось у драйвера дисплея для заголовков боковой панели, метаданные обоев и просматриваемый экран разрешались три-четыре раза, редактируемый и наведённый пресеты искались до девяти раз каждый для передачи в сетку, каждая миниатюра пресета заново перебирала все свои прямоугольники для каждой ячейки, а как только существовала хоть одна группа окон или спутниковая пара, каждая строка боковой панели заново строила собственные таблицы поиска для значков связи. Теперь имена экранов кэшируются, входные данные экрана / обоев / пресета разрешаются один раз за проход, боковая панель строит таблицы связей один раз и разделяет их между строками, а миниатюры пресетов сравнивают свои входные данные и пропускают перерисовку, когда ничего не изменилось.
- Оверлей мог оставаться на экране после щелчка по окну другого приложения. В macOS 14 и новее система может отказать Tiley в активации, если горячая клавиша нажата сразу после взаимодействия с другим приложением (например, сразу после щелчка по другому окну для закрытия предыдущего оверлея); оверлей при этом был виден, но Tiley не был активен, поэтому щелчок в другом месте никогда не вызывал деактивацию, которая его скрывает. Теперь Tiley проверяет активацию вскоре после показа оверлея и повторяет её, а если в ней по-прежнему отказано, щелчок вне окон Tiley скрывает оверлей напрямую.
- Каждый захват списка окон (в фоне после каждого переключения приложений и при каждом открытии оверлея) выполнял три-четыре отдельных обращения Accessibility на окно — подроль, положение, размер и затем заголовок — и для каждого окна заново получал список запущенных приложений, создавал новый элемент приложения Accessibility и заново перечислял экраны. Он также дважды копировал список окон на экране лишь для проверки Show Desktop / Mission Control. Теперь атрибуты каждого окна запрашиваются одним обращением, список приложений, элементы приложений и список экранов собираются один раз на захват, а обе проверки используют одну копию списка окон.
- Операции с группами окон выполняли одну и ту же работу по нескольку раз за одно действие пользователя: роспуск группы запускал полную перепроверку всех остальных групп (с повторным чтением положения каждого участника через Accessibility) и обновление значков, а повторная привязка спутников или разделение по Space распускали две и более группы подряд — так что один щелчок по парному окну мог вызвать четыре-пять обновлений значков и семь-восемь запросов списка окон; связывание, отвязка, истечение кандидатов и уничтожение окон запускали каждое своё немедленное обновление; применение раскладки отвязывало соседства у края экрана по одному с полным обновлением каждый раз; а один щелчок доходил до обработчика поднятия группы до трёх раз. Теперь множественные роспуски перепроверяют один раз в конце, завершающие обновления объединяются на следующем витке цикла событий, перепроверка передаёт обновлению уже прочитанные положения, отвязка перед раскладкой разделяет группу один раз без промежуточного обновления, а повторные вызовы поднятия для того же окна в течение 100 мс отбрасываются.
- Один счётчик версии управлял всеми представлениями оверлея, зависящими от списка окон, и увеличивался как при изменении выбора, так и при изменении списка: одно открытие оверлея увеличивало его четыре-пять раз, каждый щелчок в боковой панели — дважды, и каждое увеличение к тому же очищало кэш боковой панели по приложениям (значок, bundle ID, исходное имя), из-за чего при следующей отрисовке приложение каждой строки заново разрешалось через Launch Services с повторным чтением Info.plist. Фоновое обновление после открытия также заново публиковало список, даже если он был идентичен уже показанному. Теперь изменения выбора увеличивают отдельный счётчик, за которым следят только зависящие от выбора представления, кэш по приложениям сбрасывается только при реальном изменении набора приложений, а обновление с тем же списком больше не публикует его заново.
- Несколько групповых действий по-прежнему блокировали главный поток синхронной последовательностью перемещения окон (которая намеренно ждёт между шагами Accessibility): заполнение группы до края экрана ждало не менее 50 мс на каждого участника, обмен двух окон и выравнивание их размеров — так же, а каждое переключение спутника восстанавливало положение якоря (плюс до четырёх повторных проверок смещения) тем же способом, так что щелчок по значку или переключение спутника могли заморозить Tiley на 100–250 мс (до секунды, если приложение отклоняет рамку). Подтверждение одного окна клавишей Enter также прокручивало цикл событий 50 мс, а подтверждение на скрытое приложение оставляло оверлей на экране на время 150-мс ожидания показа. Теперь эти перемещения выполняются в фоновых потоках, состояние группы обновляется после их завершения (а подавление групповой связи удерживается до этого момента вместо фиксированных 0,1 с), подтверждение одного окна приостанавливается вместо прокрутки, а окна Tiley убираются с экрана до ожидания показа.
- После выравнивания высот (или ширин) двух связанных окон перетаскивание одного из них могло оставить пару смещённой, если приложение сообщало о перетаскивании как об одновременном перемещении и изменении размера (так делает macOS при снятии мозаики с окна, заполнявшего экран): партнёру предлагается повторить перпендикулярное смещение, но некоторые приложения его игнорируют, а привязка при отпускании, которая должна заново выровнять общие грани, решала, «общие» ли они, по кэшам, которые предшествующее устранение зазоров/перекрытий только что перезаписало реальным положением партнёра, — и заключала, что нет, оставляя рассогласование. Теперь общие грани записываются в начале перетаскивания, и привязка при отпускании использует эту запись.
- Наведение на строку в боковой панели окон оверлея заново вычисляло всё тело оверлея на этом дисплее — композицию экрана, сетку с миниатюрами окон, каждую строку пресетов и панель подсказок, — потому что состояние наведения строк хранилось в представлении верхнего уровня. Список строк боковой панели теперь является отдельным представлением, владеющим этим состоянием, так что при движении указателя по списку перерисовываются только строки.
- Ещё две затраты на каждую отрисовку оверлея: перемещение указателя по сетке заново сравнивало каждую базовую ячейку (до 144, каждая с перебором выделений), поскольку наведённая ячейка была входом всей сетки ячеек, а каждое повторное вычисление тела оверлея — наведение на пресет, изменение выбора, нажатие клавиши — заново строило список строк боковой панели и её таблицы поиска связей, хотя их входные данные не менялись. Теперь базовые ячейки — отдельное представление, сравниваемое по значению, с заливкой наведения в виде одного оверлея, а строки боковой панели и таблицы поиска мемоизируются по списку окон, тексту поиска, Spaces, конфигурации экранов и состоянию групп.
- Путь горячей клавиши нёс несколько небольших затрат при каждом нажатии или закрытии: релизные сборки при каждом нажатии спрашивали Launch Services, запущена ли отладочная сборка (этот флаг уже поддерживается наблюдателями запуска/завершения), обработчик проходил через задачу перед открытием оверлея, каждое закрытие снимало и заново регистрировало неизменённую главную горячую клавишу и пересоздавало резолвер отпечатков дисплеев (читающий производителя/модель/серийный номер каждого дисплея), а шаг после открытия копировал список окон на экране в главном потоке для обнаружения Show Desktop / Mission Control и затем читал положение целевого окна синхронным вызовом Accessibility, который авторитетное обновление делало избыточным. Теперь нажатие открывает оверлей напрямую, главная горячая клавиша остаётся зарегистрированной между закрытиями, резолвер мемоизируется по конфигурации экранов, проверка Exposé выполняется вне главного потока, а избыточное чтение Accessibility удалено.

### Удалено

- Удалено внутреннее сообщение о состоянии, которое записывалось при каждом действии с раскладкой, но нигде в интерфейсе не отображалось (наследие прежнего интерфейса), вместе с одиннадцатью более не используемыми ключами локализации во всех языках. Видимых изменений в поведении нет.

## [5.1.1] - 2026-04-25

### Добавлено

- В меню при наведении на бейдж связи группы окон теперь есть третья кнопка рядом с кнопкой перестановки: **Выровнять высоту окон** (для пар слева/справа, значок со стрелками вверх/вниз) или **Выровнять ширину окон** (для пар сверху/снизу, значок со стрелками влево/вправо). Выравнивает обе стороны бейджа (все участники группы, разнесённые по линии контакта) по перпендикулярной оси. Под «обеими сторонами» имеются в виду не только два окна, напрямую связанные бейджем, но и **все участники группы по ту же сторону линии контакта** — включая «братьев», которые не связаны напрямую между собой, но имеют общее родительское ребро (пример: сверху `[A]`, снизу `[B]` и `[C]`, оба прижаты к нижнему краю A, но между собой не связаны → щелчок «Выровнять ширину» на бейдже A↔B рассматривает `{B, C}` как одну сторону, и B+C вместе становятся такой же ширины, как A). Внутри каждой стороны окна сортируются и перераспределяются встык: крайние грани закрепляются на внешней огибающей, а соседние окна сходятся в середине своих исходных граней — чистые общие грани остаются на месте, а зазор или перекрытие равномерно распределяются между двумя окнами и закрываются. Кнопка скрыта, когда обе стороны уже выровнены и внутри тоже нет зазора или перекрытия
- Бейджи-кандидаты «сформировать группу» теперь появляются и тогда, когда вы вручную перемещаете или меняете размер окна так, что его край оказывается прижатым к краю другого окна, — а не только после применения раскладки Tiley. Бейдж появляется в момент отпускания кнопки мыши (во время самого перетаскивания/изменения размера он скрыт); щелчок по нему связывает пару в группу окон точно так же, как бейдж-кандидат после применения раскладки
- При щелчке по бейджу-кандидату «сформировать группу» меню при наведении (Разгруппировать / Поменять местами / Выровнять высоту или ширину) теперь появляется сразу же — в тот же момент, когда группа создаётся; не нужно сначала уводить курсор с бейджа и снова наводить его
- Меню при наведении (капсула с действиями) теперь плавно появляется и исчезает с эффектом fade-in/fade-out, а не возникает и пропадает скачком. Пока идёт затухание, панель бейджа сохраняет расширенный размер, чтобы капсула не обрезалась; при повторном наведении в процессе анимации сжатие отменяется
- В меню при наведении на бейдж связанной группы добавлены две новые кнопки: **Растянуть на ширину экрана** (значок `rectangle.portrait.arrowtriangle.2.outward`) и **Растянуть на высоту экрана** (значок `rectangle.arrowtriangle.2.outward`). Они пропорционально масштабируют все окна группы так, чтобы их охватывающий прямоугольник точно совпал с шириной или высотой видимой области экрана (без Dock и строки меню), при этом сохраняя относительные расстояния между участниками. Каждая кнопка скрыта, если группа уже занимает весь экран по этой оси
- При наведении курсора на бейдж связи между двумя сгруппированными реальными окнами теперь под бейджем (или над ним, если внизу не хватает места на экране) появляется небольшое меню действий: кнопка **Разгруппировать** и кнопка перестановки — **Поменять местами левое и правое окна** или **Поменять местами верхнее и нижнее окна** в зависимости от расположения пары. Сам бейдж больше не превращается в кнопку разгруппирования и служит лишь визуальным индикатором того, что окна связаны. При перестановке также снимаются все остальные связи этих двух окон с третьими окнами, поэтому после перестановки остаётся «чистая» группа из двух окон

### Исправлено

- При применении пресета компоновки с несколькими прямоугольниками, если окно не может уменьшиться до целевого прямоугольника из-за минимального размера приложения, ширина или высота соседнего окна теперь автоматически подстраивается так, чтобы общая грань оставалась выровненной (зазор пресета сохраняется). Раньше возникали наложения или неровные зазоры
- Индикатор группировки на боковой панели теперь показывает также связи-сателлиты слотов приложения, не входящие в текущую активную пространственную группу. При применении пресета с прямоугольниками, к которым привязаны приложения, и сгруппированными парами окно с неназначенной стороны регистрируется как сателлит по bundle ID назначенного приложения. Если затем повторно применить тот же пресет (или другой с тем же якорным приложением), но с другим окном, предыдущая пара выпадает из пространственного `WindowGroup`, однако сателлитная связь (поведение «поднять на передний план по клику») сохраняется. Ранее такие «фоновые, но всё ещё живые» связи не отображались на боковой панели; теперь они показываются рядом с активными пространственными партнёрами в виде иконок приложений-партнёров, и каждую можно разорвать по отдельности тем же действием «навести → щёлкнуть». Это касается и случая, когда одно окно является сателлитом нескольких якорных приложений, и случая, когда у одного bundle якорного окна зарегистрировано несколько сателлитов

### Изменено

- При применении пресета раскладки, прижимающего окно к краю экрана, теперь разрываются только те связи группы, которые проходят по той стороне изменённого окна, что ложится вплотную к краю экрана — связи на других сторонах сохраняются. Например, при горизонтальной паре A↔B и вертикальной паре A↔C применение к A раскладки «Заполнить ширину экрана» разрывает связь A↔B (поскольку правая сторона A становится правым краем экрана), а связь A↔C сохраняется, пока нижняя сторона A не доходит до нижнего края экрана. Раньше любое изменение размера через Tiley, затрагивающее лишь часть группы, распускало всю группу независимо от того, какие стороны были задействованы
- Индикатор группировки на боковой панели переработан. Вместо значка связи, плавающего между строками, теперь в каждой строке сгруппированного окна справа — непосредственно перед значком индекса — рядом друг с другом отображаются иконки приложений всех связанных окон-партнёров. При наведении курсора на иконку партнёра соответствующая строка окна-партнёра подсвечивается на боковой панели, а сама иконка (вместе с соответствующей иконкой в строке партнёра) переключается в красное состояние `x`, чтобы сразу было видно, какие два окна затрагиваются. Щелчок в состоянии `x` разрывает только эту одну связь — так у окна с несколькими связями их можно снимать поочерёдно. Место под значок индекса всегда резервируется, поэтому строки остаются выровненными, даже когда индекс не показан

## [5.1.0] - 2026-04-25

### Добавлено

- Добавлена стандартная предустановка макета «Центр»: сетка 4×4 с выделенной центральной областью 2×2, привязанная к сочетанию `C`
- В конце списка предустановок макета добавлена строка «+». Щелчок по ней создаёт предустановку с именем «Новая предустановка макета» и сразу переводит её в режим редактирования
- Группировку теперь можно задавать прямо при редактировании предустановки макета: на каждом общем ребре между областями появляется бейдж `link.badge.plus`; щелчок помечает пару как сгруппированную (бейдж переходит в «связанное» состояние, при наведении показывается значок разрыва). При наведении на предустановку в боковой панели на предпросмотре тоже показываются связанные бейджи, так что сразу видно, какие области будут сгруппированы. При применении такой предустановки соответствующие окна сразу оказываются сгруппированными — никаких дополнительных кликов
- Прямоугольники предустановки макета теперь можно привязывать к конкретному приложению. В редакторе предустановок у каждого прямоугольника есть бейдж `macwindow.badge.plus` — щёлкните, чтобы выбрать запущенное приложение (или через «Другое приложение…» найти его в файловой системе). Назначенный прямоугольник отображается как миниатюра окна с иконкой приложения вместо номера индекса; при наведении появляется ×, щелчок по которому снимает назначение. При применении предустановки в назначенный прямоугольник всегда попадает самое верхнее окно привязанного приложения (при необходимости приложение запускается и Tiley ждёт появления окна до 30 секунд). Если приложение запущено, но окон нет, отправляется системное уведомление. Если в паре сгруппированных областей назначена только одна сторона, окно, которое попало в ненаначенную сторону, связывается с окном назначенного приложения как «спутник» на время сеанса: щелчок по любому из двух также выводит партнёра на передний план

### Изменено

- Функция `debugLog` теперь использует `@autoclosure`: при выключенном журнале отладки интерполяция строк сообщений журнала полностью пропускается и не создаёт накладных расходов

### Исправлено

- Значки связи для группировки окон больше не появляются над окнами, полностью скрытыми за другим окном. После применения раскладки к большому числу окон значки показываются только между видимыми (передними) окнами; перекрытые окна исключаются из кандидатов на группировку, пока не будут выведены на передний план

### Удалено

- Удалена временная предустановка «Последний выбор», которая автоматически добавлялась после применения макета. Теперь новые предустановки создаются явно через строку «+»

## [5.0.0] - 2026-04-22

### Добавлено

- Добавлена группировка окон. После применения пресета раскладки с несколькими окнами в середине любых соприкасающихся граней появляется значок связывания (`link.badge.plus`). Щелчок по значку объединяет окна в группу: перетаскивание одного окна перемещает всех участников одновременно, изменение размера общей грани симметрично меняет размер соседнего окна, а вывод участника на передний план приподнимает остальных непосредственно под ним. При наведении на значок появляется иконка разъединения — по клику группа распадается. При закрытии окна из группы она также распадается автоматически
- Значок связи в боковой панели: в боковой панели основного окна между последовательными строками сгруппированных окон теперь отображается небольшой индикатор связи, чтобы с одного взгляда видеть, какие окна объединены. Если сгруппированное окно оказалось бы отделено от своей пары блоком заголовка приложения, оно извлекается из этого блока и размещается непосредственно под своей парой, сохраняя связь на виду

### Исправлено

- Исправлена проблема, из-за которой предпросмотры при наведении курсора и во время перетаскивания на сетке главного окна использовали стиль прямоугольника из режима редактирования пресета (залитая заливка, без заголовка) также при обычном применении раскладки; вне режима редактирования пресета теперь корректно отображается миниатюрное окно со значком приложения, именем приложения и названием окна
- Исправлено, что при применении раскладки «бок о бок» к множественному выделению одно из двух окон изредка оказывалось не в той позиции. Анимация, временно сдвигающая вниз окна, перекрывающие выбранное, продолжала выполняться после применения раскладки и перезаписывала итоговые позиции
- Исправлено, что после применения раскладки «бок о бок» размещённое окно могло медленно сползать в правый нижний угол. Отложенная очистка после скрытия главного окна могла запустить анимацию восстановления, пока только что размещённое окно всё ещё числилось в списке отодвинутых окон, и тем самым постепенно утаскивала его обратно в исходную позицию до отодвигания
